# ai

Cloudflare Worker that runs the Idea Studio's agents on a model provider (Google Gemini by default) so the app never holds a provider key. Nothing here is deployed and no real secrets are in the repo. Full setup is in `docs/AI.md`.

## Route

`POST /v1/complete` (content-type `application/json`) with `{ "agent", "input", "schema"? }` returns `{ "json": <model output> }`.

- `agent` must be in `AI_AGENTS`. `input` (an object, with `lang`) holds the user's data. The Worker owns the system prompts (`src/prompts.js`, generated by `npm run gen:ai`); a request containing `system` gets 400. Sizes are capped by `AI_MAX_*`.
- Errors are always JSON `{ "error", "retry_after"? }`: `400 bad_request`, `403 origin`, `404 not_found`, `405 method`, `413 too_large`, `415 unsupported_media`, `503 misconfigured` (no `LIMITS` KV), `504 timeout` (also a stalled request body), `429 rate_limit` (per-user) or `quota` (global cap or the provider's own quota, `retry_after` in seconds), `500 not_configured`, `502 upstream` or `bad_output`, `504 timeout`. The app falls back to its template agents on any of them.
- CORS allows only `ALLOWED_ORIGINS` (a missing or other Origin gets 403). No cookies are read or set.

## Config

Vars (in `wrangler.toml`, all strings): `ALLOWED_ORIGINS`, `AI_PROVIDER` (`gemini` or `openai` stub), `AI_MODEL`, `AI_AGENTS`, `AI_MAX_INPUT_CHARS`, `AI_MAX_SCHEMA_CHARS`, `AI_MAX_OUTPUT_TOKENS`, `AI_BODY_TIMEOUT_MS`, `AI_TIMEOUT_MS`, `AI_PER_IP_MINUTE`, `AI_PER_IP_DAY`, `AI_PER_MINUTE`, `AI_PER_DAY` (per client id), `AI_GLOBAL_DAILY`.

Secrets (`npx wrangler secret put NAME`): `GEMINI_API_KEY` (or `OPENAI_API_KEY` for the stub). Optional var `OPENAI_BASE_URL`.

KV namespace binding: `LIMITS` (`npx wrangler kv namespace create LIMITS`).

## Layout

- `src/index.js`: routing, CORS, validation, rate limits, timeout, error mapping.
- `src/providers/index.js`: the registry. `gemini.js` is the default, `openai.js` is a clearly marked untested stub, `errors.js` has `ProviderError`.

## Limits and known gaps

- Rate limits are fixed windows in KV (per minute and per day per client, plus one global daily counter, UTC days). KV is not atomic, so a burst can overshoot by a few calls.
- The client id is self-chosen, so it only adds a stricter bucket; the per-IP buckets always apply. Many IPs can still drain the global cap. A Durable Object would make the counters exact.
- The `schema` comes from the client (size-capped). The Worker's prompts are fixed, but anyone on an allowed origin can still send arbitrary `input` within the limits.
- Logs hold only provider, agent, status and duration. Never add user text, model output or keys to a log line.
